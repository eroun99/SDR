# SDR 기능 정의서 (초안)

기본 수신 기능과 확장 후보를 정리한 초안입니다. EXT 항목은 확장 후보입니다.

## 기능

| ID | 기능 | 상세 내용 |
| --- | --- | --- |
| RX-01 | 수신 설정 | PC에서 수신 입력, 중심 주파수, 샘플률, 수신 대역폭, 이득을 설정하고 적용 값을 확인한다. |
| RX-02 | I/Q 수신 | 보드에서 RF 신호를 수신해 I/Q 데이터를 PC로 전송한다. 수신 시작과 정지를 지원하고, 여러 입력을 사용하면 입력별 데이터를 구분한다. |
| RX-03 | 스펙트럼 표시 | PC에서 FFT 스펙트럼과 워터폴을 표시해 수신 신호의 주파수 분포와 시간에 따른 변화를 확인한다. |
| RX-04 | I/Q 저장 | 수신 I/Q를 파일로 저장한다. 입력 구분, 데이터 형식, 중심 주파수, 샘플률 등 재분석에 필요한 설정을 함께 기록한다. |
| RX-05 | 상태, 오류 표시 | 보드 연결 상태, 수신 상태, 수신 데이터율과 오류를 표시한다. 데이터 누락은 검출 가능한 경우 결과를 표시하고, 확인할 수 없으면 미확인으로 표시한다. |
| RX-06 | 신호 선택 | 수신 대역에서 원하는 신호의 주파수와 대역폭을 선택한다. 주파수 이동, 필터링, 샘플률 변환으로 복조에 사용할 I/Q를 추출한다. |
| RX-07 | 복조, 출력 | 선택한 신호를 지정한 변조 방식으로 PC에서 복조한다. 복조 결과를 오디오로 재생하거나 데이터로 표시, 저장한다. |
| RX-08 | 저장 데이터 재생 | 저장한 I/Q와 수신 설정을 읽어 보드 연결 없이 스펙트럼 분석과 복조를 다시 수행한다. |
| EXT-01 | 다중 신호 동시 처리 | 하나의 RF 입력에서 여러 주파수의 신호를 동시에 추출하고, 채널별로 복조하거나 저장한다. |
| EXT-02 | 신호 자동 검출 | 관측 대역에서 설정한 검출 조건을 만족하는 신호를 찾아 주파수, 검출 시각, 크기와 대역폭을 기록한다. |
| EXT-03 | 방향탐지, 빔포밍 | 여러 안테나의 I/Q를 동시에 수신하고 샘플 정렬, 위상과 이득 보정을 수행한다. 도래 방향을 추정하거나 지정한 방향의 신호를 강조하는 합성 출력을 생성한다. |
| EXT-04 | 송신 | 생성하거나 파일에서 읽은 I/Q를 보드로 전달해 RF 신호로 출력한다. 송신 시작과 정지, 중심 주파수, 샘플률, 대역폭과 출력 수준 설정을 지원한다. |

| SW-04 | 복조, 오디오 | 선택한 협대역 I/Q를 지정한 변조 방식으로 복조하고 오디오는 재생·저장, 비오디오 데이터는 표시·저장한다. 초기 수락에 사용할 복조 방식, 오디오 샘플률·채널 수와 비오디오 결과 스키마는 기준 시험 데이터와 함께 확정한다. 미지원 방식은 명시한다. 저장한 I/Q와 메타데이터를 보드 연결 없이 읽어 분석·복조를 다시 수행한다. |
| SW-05 | 파일 형식 | I/Q는 `.cs16`, 설정·포맷·처리 이력은 짝이 되는 `.json`, 복조 오디오는 `.wav`로 저장한다. `.cs16`은 I/Q 각각 signed int16, Little-endian으로 저장하고 I/Q 순서·RF 입력 순서·인터리빙 방식을 JSON에 기록한다. 협대역 처리 결과를 int16으로 변환할 때 스케일·클리핑 조건도 기록한다. 비오디오 복조 결과의 파일 표현은 SW-04의 스키마 확정 후 검증한다. 파일을 다시 읽어 샘플 수·입력 구분·메타데이터를 확인하며 저장 실패·중단 시 불완전 상태를 표시한다. |
| SW-06 | 장비 연결, 수신 설정 | 장비 주소·포트 등 확정된 연결 정보를 사용해 연결·해제하고 활성 입력, 중심 주파수, 샘플률, 수신 대역폭과 이득을 설정한다. 요청 값과 장비가 확인해 준 적용 값을 구분해 표시·기록한다. 수신 시작·정지, 응답 시간 초과, 잘못된 설정과 연결 종료를 처리한다. 제어 명령·응답 형식과 적용 값 확인 방법은 장비 인터페이스와 맞춰 검증한다. |
| SW-07 | 소켓, 스레드·큐 | TCP 기반 수신을 제안 목표로 하되 장비 측 제공 여부·포트·프로토콜은 미정이다. 수신, 처리·복조, 파일 저장, UI 작업을 분리하고 스레드/worker 또는 비동기 방식의 선택·호환성은 SW-01 환경에서 검증한다. 큐마다 최대 블록 수·바이트 수를 정해 메모리를 제한한다. UI 큐는 오래된 표시 프레임을 버리고 최신 프레임을 사용하되 표시 drop을 계수한다. 수집·저장·복조 큐 초과 시 오류·손실 계수·불완전 상태를 기록하고 수신을 정지하는 정책을 초기 목표로 한다. |
| SW-08 | 다채널 포맷, 수신 검증 | FW-04의 I int16/Q int16, Little-endian을 초기 입력 목표로 한다. 활성 입력 수·ID, I/Q 순서, channel order, 인터리빙과 입력당 샘플률은 수신 인터페이스와 명시적으로 맞춘다. 확정한 헤더·payload 길이로 TCP 프레임을 조립해 분할·병합 수신을 처리한다. 프레임 길이·입력 수·샘플 수·포맷을 검증하고 부적합 데이터는 정상 I/Q로 처리하지 않는다. 프로토콜이 제공하는 application seq/샘플 인덱스와 보드 overrun 상태, PC 수신량·큐 손실을 대조한다. 장비가 제공하지 않는 정보에 따른 누락·동시성은 미확인으로 표시한다. |
| SW-09 | 상태, 오류, 디버깅 로그 | 연결·수신 상태, 입력별 샘플 수, payload 수신량·실측 데이터율, UI 갱신율, 큐 사용량, 표시 drop, 처리 손실, seq 불연속과 보드 overrun을 구분해 표시·기록한다. 시간, 실행 환경·소스 버전, 요청/적용 설정, 프레임 오류, 시간 초과, 연결 종료, 저장·복조 오류와 정지 원인을 로그에 남긴다. 로그의 보관량도 제한하고 종료 시 소켓·worker·파일 자원을 정리한다. |

### PC SW 데이터·성능 검증 조건

- 전대역 I/Q는 활성 RF 입력별 원본 수집 데이터, 협대역 I/Q는 선택 신호의 처리 결과로 구분한다. 복조 결과에는 원본/협대역 데이터 식별자와 처리 설정을 남겨 입력을 혼동하지 않게 한다.
- 수신·캡처·저장 데이터에는 dtype, byte order, I/Q 순서, channel order/인터리빙, 활성 입력 ID·수, 입력별 샘플 수, 중심 주파수와 해당 데이터의 샘플률을 명시한다. 시작 시각·샘플 구간, 필터·샘플률 변환·복조 설정, 스케일과 검출된 손실도 기록하며 제공되지 않는 값은 미확인으로 남긴다.
- FW-02~05와 같은 조건인 입력당 5 MS/s, 2 RX, 복소 샘플당 4 byte를 사용하면 제안 payload 목표는 `5,000,000 × 2 × 4 = 40,000,000 byte/s = 40 MB/s = 320 Mb/s`이다. 이는 헤더·TCP/IP 등 overhead를 제외한 계산값이며 실측·지속 수신 보장이 아니다. 시험에서는 payload와 전체 전송량을 구분하고 PC·네트워크·디스크 조건, 시험 시간, 수신량·저장량·손실을 함께 기록한다.
- TCP는 바이트 스트림이므로 한 번의 송신/수신 호출을 한 I/Q 프레임으로 가정하지 않는다. 헤더 크기·버전·길이·상한·입력/샘플 수·포맷·application seq 또는 샘플 인덱스의 제공 여부, 종료·오류 시 동작을 장비 측과 합의한 뒤 검증한다. TCP 전송이 정상이라는 이유만으로 ADC/DMA/큐의 샘플 손실이 없다고 판정하지 않는다.
- MATLAB 소켓 API 후보를 검토할 때 데이터형·byte order·시간 초과와 blocking 동작을 확인하고 UI 작업이 수신을 지연시키지 않는지 시험한다. [MathWorks tcpclient](https://www.mathworks.com/help/matlab/ref/tcpclient.html), [read](https://www.mathworks.com/help/matlab/ref/tcpclient.read.html), [RFC 9293 §3.7](https://www.rfc-editor.org/rfc/rfc9293.html#section-3.7)는 API·TCP 동작의 참고 근거이며 이 저장소의 장비 호환성이나 처리량을 증명하지 않는다.

### PC SW 수락 기준 (구현 후 수행)

모든 결과에는 MATLAB/OS/의존성·소스 버전, 장비·설정, 입력 데이터, 절차와 관찰값을 기록한다. 미정 항목을 확정하고 시험을 통과한 범위만 지원·완료로 표시한다.

| ID | 대상 | 확인 방법과 통과 조건 |
| --- | --- | --- |
| SW-A01 | 연결·설정·종료 | 연결, 설정, 시작, 정지, 해제를 반복하고 요청/적용 값이 일치하거나 차이·거부 사유가 표시되는지 확인한다. 잘못된 주소·설정, 시간 초과와 연결 종료가 정상 데이터로 처리되지 않고 오류로 남으며 종료 후 자원이 정리되어 다시 연결할 수 있어야 한다. |
| SW-A02 | 1024/2048 캡처·포맷 | 입력마다 서로 다른 알려진 I/Q 패턴을 보내 1 RX와 2 RX에서 검증한다. 각 활성 입력에 정확히 N=1024/2048 복소 샘플이 있어야 하고 signed int16·Little-endian·I/Q·입력 순서가 기준 패턴과 일치해야 한다. 2 RX payload는 각각 8192/16384 byte여야 한다. 입력 간 샘플 정렬은 공통 인덱스 등 장비 근거가 있을 때만 확인된 것으로 기록한다. |
| SW-A03 | FFT·UI와 수집 분리 | 알려진 주파수의 시험 톤으로 두 FFT 길이의 peak 위치가 예상값의 1 bin 이내이고 축·빈 간격·Hann 설정이 맞는지 확인한다. 5 MS/s 조건의 빈 간격 계산과 10 Hz 제안 UI 목표를 각각 확인하고 실측 갱신율을 기록한다. 화면 갱신을 늦추어도 수집 샘플 수와 저장 데이터에 영향이 없거나 SW-07 정책에 따른 오류·정지가 명시되어야 한다. |
| SW-A04 | TCP framing·누락 검출 | 동일한 기준 스트림을 여러 크기로 분할하거나 여러 프레임을 합쳐 전달해도 복원 I/Q·샘플 수가 같아야 한다. 잘못된 길이·포맷, 불완전 프레임, application seq 불연속, overrun을 주입해 오류와 검출 계수를 확인한다. seq/overrun 정보가 없는 경우는 누락 미확인으로 표시해야 한다. |
| SW-A05 | 유한 큐·부하 | 큐 상한과 로그 보관량을 시험 전에 설정하고 UI·디스크·복조 처리를 의도적으로 지연한다. 큐가 상한을 넘지 않고 UI drop과 수집/처리 손실이 별도 계수되어야 하며, 수집·저장·복조 큐 초과 시 불완전 상태·원인 로그와 수신 정지를 확인한다. |
| SW-A06 | payload 처리량 | 제안 조건인 5 MS/s × 2 RX로 60초 이상 수신·저장하며 UI도 실행한다. 안정화 후 측정 구간의 실측 payload 데이터율이 40 MB/s 제안 목표에 도달해야 한다. 정상 완료된 샘플 구간의 예상 payload `입력당 샘플 수 × 활성 입력 수 × 4 byte`가 PC 수신·저장량과 일치하고, 제공되는 seq가 연속이며 overrun·처리 손실이 0이어야 한다. 장비 손실 정보가 없으면 처리량 실측만 기록하고 종단 간 무손실 수락은 미확인으로 둔다. 목표 미달·오류·정지 시 조건과 계수를 기록하고 성능 완료로 표시하지 않는다. |
| SW-A07 | 추출·복조·데이터 구분 | 초기 신호 1개에 대해 알려진 시험 데이터로 선택 주파수, 필터, 출력 샘플률과 원본/협대역/복조 결과의 연결 정보를 확인한다. 확정한 복조 방식의 기준 출력·비교 허용오차를 시험 전에 정하고 결과가 이를 만족해야 한다. 오디오 재생·저장 또는 비오디오 표시·저장은 해당 방식에 맞게 검증한다. |
| SW-A08 | 파일 저장·재분석 | `.cs16`과 `.json`을 다시 읽어 입력별 샘플 수·포맷·값이 저장 전과 일치하고, 보드 연결 없이 같은 설정으로 분석·복조 결과를 재현해야 한다. 협대역 양자화는 기록한 스케일·허용오차로 비교한다. `.wav` 샘플률·채널 수·길이를 확인하고 저장 실패·중단·메타데이터 불일치는 오류/불완전 상태로 식별되어야 한다. |
